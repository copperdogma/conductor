# Project methodology

The Ideal describes desired user and development experiences. The Spec records
current constraints and chosen mechanisms. Neither is generated by package
installation. State holds mutable planning truth, while graph and story index
are compiled projections. Authored stories own implementation acceptance and
proof; ADRs own settled decisions. Research notes retain source evidence and
uncertainty without silently becoming requirements.

State uses JSON syntax in `docs/methodology/state.yaml`, matching the portable
compiler's supported YAML subset. `project` holds `name` and `mission`;
`categories` maps local category keys to `spec_ref`, `substrate`, `phase`, and
`summary`. Category references point to authored `spec:N` headings. Phases are
`climb` (capability), `hold` (efficiency/simplicity), and `converge` (remove a
compromise when its deletion proof supports it). Use optional `lanes` with
`status`, `reason`, and a `trigger` for deferred work. Do not invent history.

The installed `product-workflow.md` reference explains daily routing. Story
sources use `story-NNN-slug.md` with frontmatter; generated files are not edited
by hand. Core package checks prove internal scaffold consistency. Product
correctness requires the target project's own checks, fixtures and acceptance.
